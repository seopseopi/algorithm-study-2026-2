# 1931. 회의실 배정

- 학습 주제: 정렬, 탐욕적 알고리즘
- 사용 언어: C++

## 문제 분석
하나의 회의실에서 시간이 겹치지 않게 진행할 수 있는 회의의 최대 개수를 구하는 문제이다.
회의가 최대 100,000개이므로 모든 선택 조합을 확인하는 방법은 비효율적이다.
시작 시각이 빠른 회의를 먼저 고르면 긴 회의 때문에 다른 회의를 놓칠 수 있다.
따라서 종료 시각이 빠른 회의부터 확인하고, 이전에 선택한 회의와 겹치지 않으면 선택했다.

## 풀이 과정
1. 각 회의를 (종료 시각, 시작 시각) 순서로 저장한다.
2. 종료 시각을 기준으로 오름차순 정렬한다. 종료 시각이 같으면 시작 시각이 빠른 순서로 정렬한다.
3. 마지막으로 선택한 회의의 종료 시각 last와 선택한 개수 cnt를 0으로 초기화한다.
4. 정렬된 회의를 앞에서부터 확인한다.
5. 현재 회의의 시작 시각이 last 이상이면 선택하고, cnt를 증가시킨다.
6. last를 선택한 회의의 종료 시각으로 갱신한다.
7. 모든 회의를 확인한 뒤 cnt를 출력한다.

가능한 회의 중 가장 빨리 끝나는 회의를 선택하면 다음 회의를 시작할 수 있는 시간을 가장 일찍 확보할 수 있다.
최대로 선택한 일정의 첫 회의를 더 일찍 끝나는 회의로 바꿔도, 뒤에 배정한 회의들은 그대로 진행할 수 있다.
같은 선택을 남은 회의에도 반복할 수 있으므로 종료 시각이 빠른 회의부터 선택하는 방법을 사용할 수 있다.

pair의 first에는 종료 시각, second에는 시작 시각을 저장했다.
따라서 sort를 사용하면 종료 시각, 시작 시각 순서로 정렬된다.

## 복잡도
회의의 개수를 N이라고 할 때, 정렬에 O(N log N), 회의 선택에 O(N)이 필요하다.
전체 시간 복잡도는 O(N log N)이다.
회의 정보를 저장하는 공간은 O(N)이다.

## 실행 확인
예제 입력을 실행하여 출력이 4인 것을 확인했다.
다음 경계 조건도 실행하여 확인했다.

| 확인 내용 | 회의 목록 (시작, 종료) | 출력 |
| --- | --- | --- |
| 회의가 하나인 경우 | (0, 0) | 1 |
| 회의가 모두 겹치는 경우 | (1, 5), (2, 6), (3, 7) | 1 |
| 종료 직후 다음 회의가 시작하는 경우 | (1, 2), (2, 3), (3, 4) | 3 |
| 종료 시각이 같고 길이가 0인 회의가 있는 경우 | (2, 2), (1, 2), (2, 3) | 3 |
| 시작과 종료 시각이 같은 회의가 반복되는 경우 | (0, 0), (0, 0), (0, 0) | 3 |
| 가장 먼저 시작하는 회의가 긴 경우 | (1, 10), (2, 3), (3, 4), (4, 5) | 3 |

## 배운 점
그리디 알고리즘은 단순히 좋아 보이는 회의를 고르는 것이 아니라, 이후 선택할 수 있는 회의의 기회를 줄이지 않는 기준이 필요하다는 것을 이해했다.
또한 회의가 끝나는 순간 다음 회의가 시작할 수 있으므로 비교 조건에 >가 아니라 >=를 사용해야 한다.
종료 시각이 같은 경우에도 시작 시각을 함께 고려해야 한다. 예를 들어 (2, 2)를 (1, 2)보다 먼저 선택하면 두 회의를 모두 선택하지 못한다.
정렬 기준과 경계 조건을 정확하게 반영하는 것이 중요하다는 점을 배웠다.
