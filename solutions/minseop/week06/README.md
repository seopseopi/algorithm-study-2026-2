# BOJ 1744. 수 묶기

- 문제 안내: [6주차 공통 문제 문서](../../../problems/week06/README.md)
- 백준 문제 주소: https://www.acmicpc.net/problem/1744
- 난이도: Gold IV
- 구현 언어: C++17

## 1. 처음 확인한 조건

수열의 크기는 50보다 작고 각 수는 -1,000 이상 1,000 이하입니다. 각 수는 다른 위치의 수와 최대 한 번 묶을 수 있으며, 묶은 두 수는 곱하고 묶지 않은 수는 그대로 더합니다.

## 2. 단순한 풀이가 비효율적인 이유

각 수를 묶지 않거나 다른 수와 묶는 모든 방법을 확인하면 경우의 수가 빠르게 증가합니다. 수의 성질에 따라 묶는 기준을 정하면 모든 조합을 탐색하지 않아도 됩니다.

## 3. 선택한 알고리즘과 핵심 아이디어

1보다 큰 양수는 내림차순으로 정렬해 큰 수부터 두 개씩 곱합니다. 0 이하의 수는 오름차순으로 정렬해 작은 수부터 두 개씩 곱합니다. 1은 다른 수와 곱하지 않고 각각 더합니다. 각 그룹에서 짝이 없이 남은 수는 그대로 더합니다.

## 4. 알고리즘이 올바른 이유

1보다 큰 정수 두 개는 곱한 값이 합보다 작지 않으므로 묶는 것이 유리합니다. `a ≥ b ≥ c ≥ d > 1`이면 `ab + cd ≥ ac + bd`이므로 큰 수끼리 묶는 선택이 최적입니다. 음수도 작은 수끼리 묶으면 양수 곱을 만들고, 같은 교환 논리로 그 절댓값이 큰 수부터 묶는 것이 유리합니다. 음수가 하나 남을 때 0이 있으면 곱해 없앨 수 있습니다. 1은 어떤 수와 곱해도 따로 더하는 것보다 유리하지 않으므로 그대로 더합니다.

## 5. 시간·공간 복잡도

두 그룹을 정렬하는 데 `O(N log N)`, 나머지 순회에 `O(N)`이 걸립니다. 수열을 저장하는 공간은 `O(N)`입니다.

## 6. 구현 시 주의할 경계 조건

- 1은 곱하지 않고 더합니다.
- 0은 짝이 없는 음수를 없애는 데 사용할 수 있습니다.
- 각 그룹에 수가 홀수 개라면 마지막 수를 그대로 더합니다.
- 수가 하나뿐인 경우에도 그 수가 그대로 답이 됩니다.

## 7. 테스트 결과

C++17로 경고 옵션을 켜고 컴파일했습니다. 백준 제출과 정답 판정은 확인하지 않았습니다.

- 공통 문서 예제 → `15`
- `-1, 0` → `0`, `1, 2` → `3`, `1, 1` → `2`
- 음수 하나 `-5` → `-5`, `0, 0` → `0`
- 음수 세 개 `-3, -2, -1` → `5`, 양수 세 개 `2, 3, 4` → `14`
- 소규모 무작위 입력 200개를 가능한 모든 묶기를 탐색하는 기준 풀이와 비교해 일치했습니다.

## 8. 학습 포인트

탐욕적 선택은 입력의 특성에 따라 기준이 달라질 수 있습니다. 곱셈에서 0과 1의 성질을 별도로 고려하고, 정렬 후 짝을 만드는 순서가 최적인 이유를 교환 논증으로 설명할 수 있습니다.
