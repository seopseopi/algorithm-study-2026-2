# BOJ 1715. 카드 정렬하기

- 문제 안내: [5주차 공통 문제 문서](../../../problems/week05/README.md)
- 백준 문제 주소: https://www.acmicpc.net/problem/1715
- 난이도: Gold IV
- 구현 언어: C++17

## 1. 처음 확인한 조건

카드 묶음은 최대 100,000개이고 각 묶음의 크기는 1 이상 1,000 이하입니다. 두 묶음을 합칠 때 두 크기의 합만큼 비교 횟수가 늘어나며, 합쳐진 묶음도 이후에 다시 합칠 수 있습니다.

## 2. 단순한 풀이가 비효율적인 이유

합치는 순서의 모든 경우를 확인하면 묶음이 많아질수록 경우의 수가 급격히 증가합니다. 매번 모든 묶음을 다시 정렬하거나 선형 탐색으로 최소 두 개를 찾는 방식도 많은 입력에서 비효율적입니다.

## 3. 선택한 알고리즘과 핵심 아이디어

최소 힙을 이용해 현재 가장 작은 두 묶음을 꺼내 합칩니다. 두 크기의 합을 총 비교 횟수에 더하고, 새 묶음을 다시 힙에 넣습니다. 묶음이 하나 남을 때까지 이 과정을 반복합니다.

## 4. 알고리즘이 올바른 이유

합치는 과정을 이진 트리로 나타내면 각 카드 묶음의 크기는 그 묶음이 합쳐지는 횟수만큼 총비용에 더해집니다. 최적 트리에서 가장 깊은 형제 두 위치에는 가장 작은 두 묶음을 놓을 수 있습니다. 더 큰 묶음과 위치를 바꾸어도 비용이 증가하지 않기 때문입니다. 따라서 가장 작은 두 묶음을 먼저 합치는 최적해가 존재합니다. 이 둘을 합친 하나의 묶음으로 바꾼 뒤에도 같은 논리를 반복할 수 있으므로 이 방법은 최소 비용을 구합니다.

## 5. 시간·공간 복잡도

힙에 묶음을 넣고 `N - 1`번 합치는 과정에서 각 삽입과 삭제에 `O(log N)`이 걸리므로 전체 시간 복잡도는 `O(N log N)`입니다. 힙에 최대 `N`개를 저장하므로 공간 복잡도는 `O(N)`입니다.

## 6. 구현 시 주의할 경계 조건

- 묶음이 하나라면 합칠 필요가 없으므로 답은 0입니다.
- 합친 묶음을 다시 힙에 넣어 이후 선택에 포함합니다.
- 합친 크기와 총 비교 횟수는 `long long`으로 저장합니다.

## 7. 테스트 결과

C++17로 경고 옵션을 켜고 컴파일했습니다. 백준 제출과 정답 판정은 확인하지 않았습니다.

- 공통 문서 예제 `5, 10, 20, 30` → `115`
- 묶음 하나 `1000` → `0`
- 같은 크기 네 묶음 `1, 1, 1, 1` → `8`
- 크기가 다른 두 묶음 `1, 1000` → `1001`
- 소규모 무작위 입력 100개를 모든 합치기 순서를 탐색하는 기준 풀이와 비교해 일치함을 확인했습니다.

## 8. 학습 포인트

현재 가장 작은 두 묶음을 먼저 합치는 선택이 전체 비용을 최소화하는 이유를 합치기 트리로 설명할 수 있습니다. 최소 힙은 새 묶음이 계속 추가되는 상황에서 작은 값을 반복해서 선택하는 데 유용합니다.
