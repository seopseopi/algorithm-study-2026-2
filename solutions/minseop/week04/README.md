# BOJ 1931. 회의실 배정

- 문제 안내: [4주차 공통 문제 문서](../../../problems/week04/README.md)
- 난이도: Gold V
- 구현 언어: C++17

## 1. 처음 확인한 조건

회의는 최대 100,000개이며, 한 회의가 끝나는 시각에 다른 회의를 시작할 수 있습니다. 시작과 종료 시각이 같은 회의도 있습니다.

## 2. 단순한 풀이가 비효율적인 이유

회의를 선택하는 모든 부분집합을 검사하면 경우의 수가 최대 `2^N`이어서 입력 크기를 감당할 수 없습니다.

## 3. 선택한 알고리즘과 핵심 아이디어

회의를 종료 시간이 빠른 순으로 정렬하고, 종료 시간이 같다면 시작 시간이 빠른 순으로 정렬합니다. 앞에서부터 보면서 마지막으로 선택한 회의의 종료 시간 이상에 시작하는 회의를 선택합니다.

## 4. 알고리즘이 올바른 이유

현재 선택할 수 있는 회의 중 가장 먼저 끝나는 회의를 선택하면 이후에 사용할 수 있는 시간이 가장 많이 남습니다. 최적 배정의 첫 회의를 이 회의로 바꿔도 나머지 회의와 겹치지 않으므로 최적 개수를 유지할 수 있습니다. 같은 논리를 남은 회의에 반복하면 탐욕적 선택으로 최적해를 얻습니다. 종료 시간이 같을 때 시작 시간이 빠른 회의를 먼저 보면, 같은 시각에 끝나는 길이 0 회의도 그 뒤에 선택할 수 있습니다.

## 5. 시간·공간 복잡도

정렬에 `O(N log N)`, 이후 순회에 `O(N)`이 걸립니다. 회의 목록에 `O(N)` 공간을 사용합니다.

## 6. 구현 시 주의할 경계 조건

- 시작 시간이 이전 종료 시간과 같아도 선택할 수 있으므로 `>=`로 비교합니다.
- 종료 시간이 같다면 시작 시간이 빠른 순으로 정렬합니다.
- 시간은 0 이상이므로 최초 종료 시간을 0으로 둡니다.
- 시각의 최대값 `2³¹ - 1`은 32비트 부호 있는 정수에 들어갑니다.

## 7. 테스트 결과

C++17로 경고 옵션을 켜고 컴파일했습니다. 백준 제출 및 정답 판정은 확인하지 않았습니다.

- 공통 문서 예제: `4`
- `(1, 1)`, `(0, 1)`, `(1, 1)`: 종료 시간이 같고 길이가 0인 회의를 포함해 `3`

## 8. 학습 포인트

탐욕법에서는 선택 기준을 정한 뒤 그 선택이 최적해를 해치지 않는다는 근거까지 설명해야 합니다. 정렬의 동점 처리도 가능한 선택에 영향을 줍니다.
