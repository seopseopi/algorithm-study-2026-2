# 1715. 카드 정렬하기

- 문제: https://www.acmicpc.net/problem/1715
- 언어: C++17
- 코드: [1715.cpp](1715.cpp)

## 문제 분석

두 묶음을 합칠 때마다 두 크기의 합만큼 비용이 발생한다. 합친 묶음도 다시 합쳐질 수 있으므로, 먼저 합친 카드들은 이후 비용에 여러 번 포함된다. 따라서 현재 가장 작은 두 묶음을 반복해서 합친다. 처음 한 번 정렬하는 것만으로는 부족하고, 새 묶음도 포함해 최솟값을 다시 구해야 한다.

## 풀이

1. 모든 카드 묶음의 크기를 최소 힙에 넣는다.
2. 힙에 묶음이 두 개 이상 남아 있으면 가장 작은 두 값을 꺼낸다.
3. 두 값의 합을 정답에 더하고, 합친 크기를 힙에 다시 넣는다.
4. 묶음이 하나 남으면 누적 비용을 출력한다.

묶음이 처음부터 하나라면 반복문을 실행하지 않아 0을 출력한다. 누적 비용과 묶음 크기는 `long long`으로 저장한다.

## 정당성

합치는 과정을 이진 트리로 보면 원래 묶음은 잎이고, 각 묶음의 크기는 자신의 깊이만큼 총비용에 더해진다. 가장 깊은 잎 중에는 형제인 두 잎이 존재한다. 가장 작은 두 크기를 그 자리에 배치해도 비용은 증가하지 않는다. 작은 값을 더 깊은 위치로 옮기고 큰 값을 더 얕은 위치로 옮기면 크기와 깊이의 곱의 합이 증가하지 않기 때문이다.

따라서 가장 작은 두 묶음이 형제로 합쳐지는 최적해가 존재한다. 이 두 잎을 합이 같은 하나의 묶음으로 축약하면, 원래 문제의 비용은 축약된 문제의 비용에 두 묶음의 합을 더한 값이다. 축약된 문제에도 같은 논리를 적용할 수 있으므로, 매번 가장 작은 두 묶음을 합치는 방법은 최적이다.

## 복잡도

- 시간: O(N log N). 초기 삽입 N번과 병합 N-1번에서 힙 연산을 수행한다.
- 공간: O(N). 최소 힙에 묶음 크기를 저장한다.

## 예제

`5, 10, 20, 30`은 `5+10=15`, `15+20=35`, `30+35=65` 순서로 합친다. 총비용은 `15+35+65=115`이다.
