# 1931. 회의실 배정

- 알고리즘: 정렬, 탐욕적 알고리즘
- 언어: C++17
- 코드: [1931.cpp](1931.cpp)

## 문제 분석

N개의 회의 중 시간이 겹치지 않는 회의를 최대한 많이 선택한다. N이 최대 100,000이므로 모든 조합을 확인하기는 어렵다. 회의가 끝나는 즉시 다음 회의를 시작할 수 있으며, 시작과 종료 시간이 같은 회의도 존재한다.

시작 시간이 빠른 회의를 고르면 긴 회의 하나가 여러 회의를 막을 수 있다. 예를 들어 (0, 10)보다 (1, 2), (2, 3)을 선택하는 편이 낫다. 길이가 짧은 회의부터 고르는 것도 최적이 아니다. (0, 3), (2, 4), (3, 6)에서는 가장 짧은 (2, 4)를 먼저 고르면 나머지 두 회의를 선택하지 못한다.

## 풀이

1. 종료 시간 오름차순으로 정렬하고, 종료 시간이 같으면 시작 시간 오름차순으로 정렬한다.
2. 마지막으로 선택한 회의의 종료 시간을 0으로 초기화한다. 모든 시간은 0 이상이므로 첫 회의도 선택할 수 있다.
3. 시작 시간이 마지막 종료 시간 이상이면 선택하고 종료 시간을 갱신한다.
4. 선택한 회의 수를 출력한다.

코드에서는 (종료 시간, 시작 시간)을 pair에 저장해 기본 정렬을 사용한다.

## 그리디가 올바른 이유

현재 선택한 회의 뒤에 배치할 수 있는 회의 중 가장 빨리 끝나는 회의를 G라고 하자. 남은 회의를 최대한 많이 고른 어떤 최적 배치의 첫 회의를 O라고 하면 G의 종료 시간은 O의 종료 시간 이하이다. O를 G로 바꾸어도 그 뒤의 회의는 여전히 배치할 수 있고 회의 수도 줄지 않는다. 따라서 G로 시작하는 최적 배치가 존재한다. 이 논리를 남은 회의에도 반복하면 그리디가 최대 개수를 선택한다.

종료 시간이 같은 경우에는 시작 시간이 빠른 순서가 필요하다. (1, 2), (2, 2)가 있다면 이 순서로 두 회의를 모두 선택할 수 있다. 반대 순서에서는 (1, 2)를 놓친다. 같은 시간의 길이 0인 회의가 여러 개 있어도 각각 선택할 수 있으므로 중복을 제거하지 않는다. 선택 조건은 start >= lastEnd이다.

## 예제

공통 문제 예제에서는 (1, 4), (4, 6), (6, 6), (6, 8)을 선택하므로 정답은 4이다.

## 복잡도

- 시간: 정렬 O(N log N), 순회 O(N)이므로 전체 O(N log N)
- 공간: 회의를 저장하는 O(N)

## 검증

공통 예제, 종료 시간이 같은 회의, 길이 0인 중복 회의, 최대 시간 값, 최대 N 입력을 확인했다. 작은 무작위 입력은 부분집합 완전탐색 결과와 비교했다. 로컬 검증이며 백준 제출 결과는 아니다.
