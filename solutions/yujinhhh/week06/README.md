# 1744. 수 묶기

- 문제: https://www.acmicpc.net/problem/1744
- 언어: C++17
- 코드: [1744.cpp](1744.cpp)

## 문제 분석과 풀이

각 수는 한 번만 묶을 수 있고, 위치와 관계없이 짝을 고를 수 있다. 부호와 값에 따라 나누어 정렬한다.

1. 1은 곱하는 것보다 그대로 더하는 것이 유리하므로 즉시 정답에 더한다.
2. 1보다 큰 양수는 내림차순으로 정렬하고 앞에서부터 두 개씩 곱한다.
3. 음수와 0은 함께 오름차순으로 정렬하고 앞에서부터 두 개씩 곱한다.
4. 각 그룹에 수가 하나 남으면 그대로 더한다.

음수는 절댓값이 큰 것부터 짝지어진다. 음수가 홀수 개이고 0이 있으면 마지막 음수가 0과 묶여 손실이 사라진다. 0이 없다면 절댓값이 가장 작은 음수 하나가 남는다. 0만 남으면 그대로 더해도 결과는 같다.

## 정당성

1과 어떤 정수 x를 묶은 결과 x보다 따로 더한 x+1이 크다. 양수와 음수를 곱하면 따로 더할 때보다 유리하지 않으며, 양수와 0을 묶으면 양수만 잃는다. 따라서 1은 따로 더하고, 1보다 큰 양수와 0 이하의 수를 분리할 수 있다.

2 이상의 정수 a, b는 ab >= a+b이므로 가능한 한 짝짓는다. a >= b >= c >= d인 양수 네 개에서 인접한 큰 수끼리 묶은 ab+cd는 ac+bd보다 (a-d)(b-c)만큼, ad+bc보다 (a-c)(b-d)만큼 크거나 같다. 수가 홀수 개일 때 a >= b >= c >= 2라면 ab+c >= ac+b이고 ab+c >= bc+a이므로 작은 수를 남기는 것이 유리하다. 이런 교환을 반복하면 내림차순의 인접한 두 수를 묶는 최적해를 얻는다.

음수 두 개를 곱하면 양수가 되어 따로 더하는 것보다 유리하다. 절댓값을 기준으로 보면 위 양수의 교환 논리가 동일하게 적용되어 절댓값이 큰 음수끼리 묶는 것이 최적이다. 음수가 홀수 개면 가장 작은 절댓값을 남기며, 0이 있으면 그 음수와 묶는다. 따라서 음수와 0을 오름차순으로 정렬해 인접하게 묶는 방식도 최적이다.

## 복잡도

- 시간: O(N log N). 정렬 이후 순회는 O(N)이다.
- 공간: O(N). 두 그룹을 저장한다.

## 검증

- 공통 문제 예제: `-3, -2, 0, 1, 2, 4` → `15`
- 1 처리: `1, 1, 2, 3` → `8`
- 홀수 음수와 0: `-5, -3, -1, 0` → `15`
- 0 없는 홀수 음수: `-5, -3, -1` → `14`
- 단일 원소, 모두 0, 최댓값·최솟값을 포함한 경우도 확인한다.
- 작은 입력은 모든 짝짓기와 단독 선택을 탐색하는 완전 탐색 결과와 비교한다.
