# 4주차 · BOJ 1931 회의실 배정 (Gold V)

- 언어: C++17
- 코드: [BOJ_1931.cpp](BOJ_1931.cpp)
- 핵심 기법: 정렬, 탐욕적 알고리즘

## 문제 분석

회의실 하나에 시간이 겹치지 않도록 회의를 골라, **진행할 수 있는 회의 수를 최대화**해야 합니다.

- `N ≤ 100,000`이라 회의 조합을 모두 확인하는 방법은 불가능합니다.
- 한 회의가 끝나는 시각에 다음 회의를 바로 시작할 수 있고, 시작 시간과 종료 시간이 같은 회의도 있습니다.

결국 "어떤 기준으로 회의를 하나씩 골라 나가면 항상 최대가 되는가"를 찾는 문제입니다.

## 선택 기준 비교

| 기준 | 반례 | 문제점 |
| --- | --- | --- |
| 시작 시간이 빠른 순 | `(1, 10)`, `(2, 3)`, `(4, 5)` | `(1, 10)`을 고르면 1개, 실제 최댓값은 2개 |
| 진행 시간이 짧은 순 | `(1, 5)`, `(4, 7)`, `(6, 10)` | 짧은 `(4, 7)`이 양쪽과 겹쳐 1개, 실제 최댓값은 2개 |
| **종료 시간이 빠른 순** | 없음 | 아래 근거 참고 |

### 종료 시간 기준이 최적인 이유 (교환 논증)

최적해에서 첫 번째로 고른 회의를 `O₁`, 종료 시간이 가장 빠른 회의를 `G₁`이라 하면 `G₁`의 종료 시간 ≤ `O₁`의 종료 시간입니다. 따라서 `O₁`을 `G₁`으로 바꿔도 뒤의 회의들과 겹치지 않고, 회의 수는 그대로입니다. 즉 가장 일찍 끝나는 회의를 고르는 선택은 항상 어떤 최적해에 포함되고, 남은 회의에 같은 논리를 반복하면 전체가 최적이 됩니다.

직관적으로는 **일찍 끝날수록 뒤에 남는 시간이 길어진다**는 뜻입니다.

## 풀이

1. 회의를 `(종료 시간, 시작 시간)` 쌍으로 저장해 오름차순 정렬합니다.
2. 마지막으로 선택한 회의의 종료 시간 `lastEnd`를 0으로 둡니다.
3. 정렬된 순서대로 보며 `시작 시간 >= lastEnd`이면 선택하고 `lastEnd`를 갱신합니다.

### 주의한 점

- **등호 포함**: 끝나는 시각에 바로 시작할 수 있으므로 `>`가 아니라 `>=`로 비교합니다.
- **종료 시간이 같을 때 시작 시간 오름차순**: 길이가 0인 회의가 있으면 순서가 결과에 영향을 줍니다.

  | 입력 | 시작 시간 오름차순 | 시작 시간 내림차순 |
  | --- | --- | --- |
  | `(1, 2)`, `(2, 2)`, `(2, 2)` | `(1,2) → (2,2) → (2,2)` = **3개** | `(2,2) → (2,2)` 후 `(1,2)` 탈락 = 2개 |

  `pair`를 `(종료, 시작)` 순서로 저장하면 기본 정렬만으로 두 조건이 함께 처리됩니다.

## 예제 따라가기

정렬 결과: `(1,4)`, `(3,5)`, `(4,6)`, `(6,6)`, `(6,8)` (시작, 종료 기준 표기)

| 회의 | lastEnd | 시작 ≥ lastEnd? | 결과 |
| --- | --- | --- | --- |
| (1, 4) | 0 | 1 ≥ 0 | 선택 → lastEnd = 4 |
| (3, 5) | 4 | 3 ≥ 4 ✗ | 건너뜀 |
| (4, 6) | 4 | 4 ≥ 4 | 선택 → lastEnd = 6 |
| (6, 6) | 6 | 6 ≥ 6 | 선택 → lastEnd = 6 |
| (6, 8) | 6 | 6 ≥ 6 | 선택 → lastEnd = 8 |

답은 **4**입니다.

## 복잡도

- 시간: 정렬 `O(N log N)` + 선택 `O(N)` → `O(N log N)`
- 공간: `O(N)`

## 검증

- 예제 입력 → `4` 출력 확인
- 종료 시간이 같은 길이 0 회의 반례(`(1,2)`, `(2,2)`, `(2,2)`) → `3` 출력 확인
- 무작위 소형 입력 500개를 모든 부분집합을 확인하는 완전 탐색 결과와 비교해 모두 일치
- 최대 크기 입력(`N = 100,000`)에서 약 0.03초
